# Типы изменений и выражения

Как строка **Изменить объект / переменную** вычисляет новое значение: фиксированное значение, копия другого поля, выражение, текст по шаблону, дата со сдвигом, счётчик, очистка, дописывание, таблица соответствия или агрегат по записям CRM.

Типы изменения (колонка **Тип изменения** строки; `aggregate` и типы с дополнительными полями — `separator`, `map`, `list`
и т. п. — задаются через API: редактор сохраняет у строки только `target`, `change_type`, `value` и `save_to_crm`):

| UI (RU) | UI (EN) | Код | В **Новом значении** |
|---|---|---|---|
| **Равен значению** | Set to value | `set_value` | само значение |
| **Равен переменной** | Set from variable | `set_from_variable` | путь к другому полю |
| **Расчёт** | Calculate | `calculate` | выражение |
| **Шаблон** | Template | `template` | текст с подстановками `{{ … }}`, см. [Шаблон](#шаблон) |
| **Сдвиг даты** | Date shift | `date_shift` | база, сдвиг и время в отдельных полях, см. [Сдвиг даты](#сдвиг-даты) |
| **Увеличить на** / **Уменьшить на** | Increment by / Decrement by | `increment` / `decrement` | шаг (по умолчанию 1), см. [Увеличить / уменьшить на](#увеличить--уменьшить-на) |
| **Очистить** | Clear | `clear` | не нужно, см. [Очистить](#очистить) |
| **Дописать в конец** / **в начало** / **Удалить из списка** | Append / Prepend / Remove from list | `append` / `prepend` / `remove` | шаблон текста или элементы списка, см. [Дописать](#дописать-в-конец--в-начало-удалить-из-списка) |
| **По таблице соответствия** | Map | `map` | поле-источник и таблица, см. [По таблице соответствия](#по-таблице-соответствия) |
| **Агрегат по записям** | Aggregate over records | `aggregate` | функция, поле и источник записей, см. [Агрегат по записям](#агрегат-по-записям) |

Те же типы изменения работают в действии [Записать в переменную процесса](actions.md#записать-в-переменную-процесса)
(`set_variable`) — для промежуточных значений, которые не сохраняются в CRM, — и в правилах
[Изменить записи списка](actions.md#изменить-записи-списка) (`update_records`).

## Равен значению

Записывает текст из **Нового значения** в поле назначения как есть.

- Допустимые значения: любой текст или число; пустое значение записывает пустую строку.
- Пример: цель `v1.rating`, значение `VIP`.
- Ошибка сервера: `Value must be a string or a number` (возможна только через API, например если значение — массив).

## Равен переменной

Копирует значение другого поля — объекта события или любой переменной.

- **Новое значение** — путь: `object.phone`, `v1.name`, `v2.sale`.
- Если исходного поля нет (или переменная пустая), в цель записывается пустое значение (`null`).
- Пример: цель `object.description`, значение `v1.name` — контакт получает название своего контрагента (сценарий **Contact: copy account name**).
- Ошибки: `Действие 1: укажите значение`; сервер: `Field path is required`, `Variable "v3" is not defined at this point`, `"v1" must point to a field, e.g. v1.name`.

## Расчёт

Вычисляет значение по выражению. Нажмите **Справка по выражениям «Расчёт»** (или значок `?` в строке), чтобы увидеть краткую памятку прямо в редакторе.

Тот же язык выражений работает в **условиях**: `"value_type": "expression"` вычисляет правую часть условия (например,
`v1.credit_limit * 0.8`), см. [Условия запуска → Сравнение с выражением](triggers-and-conditions.md#сравнение-с-выражением).

```text
round(object.amount * 0.9, 2)
concat('Discount applied, new amount: ', object.amount)
upper(trim(object.name))
```

### Синтаксис

| Элемент | Как записывается | Примеры |
|---|---|---|
| Число | цифры, можно с десятичной точкой | `10`, `0.9`, `.5` |
| Строка | в одинарных или двойных кавычках; `\` экранирует следующий символ | `'abc'`, `"Call back: "`, `'it\'s'` |
| Путь к полю | `object.<поле>` или `<переменная>.<поле>`; вложенные поля — через дополнительные точки | `object.amount`, `v1.price`, `v1.address.city` |
| Литералы | `true`, `false`, `null` | `object.is_active == true` |
| Список | `[a, b, …]` | `[object.a, object.b] == [1, 2]` |
| Арифметика | `+` `-` `*` `/` `%` | `object.amount * 0.9 + 10` |
| Унарный минус | `-` перед значением | `-object.amount` |
| Сравнение | `==` `!=` `<` `<=` `>` `>=` | `object.amount > 100000` |
| Логика | `and` `or` `not` | `object.probability >= 50 and not object.closed` |
| Скобки | `(` … `)` | `(object.price - object.discount) * object.qty` |
| Вызов функции | `имя(аргумент, …)`, регистр имени не важен | `round(object.amount, 2)` |

**Синонимы:** `=` — то же, что `==`; `<>` — то же, что `!=`; `&&`, `||`, `!` — то же, что `and`, `or`, `not`.

**Приоритет операторов** (сверху вниз — от слабого к сильному; операторы одного уровня выполняются слева направо):

| Уровень | Операторы | Как читается |
|---|---|---|
| 1 | `or`, `\|\|` | `a or b and c` = `a or (b and c)` |
| 2 | `and`, `&&` | `a and b or c` = `(a and b) or c` |
| 3 | `not`, `!` | `not a == b` = `not (a == b)` |
| 4 | `==` `!=` `<` `<=` `>` `>=` (и синонимы) | не объединяются в цепочку: `1 < 2 < 3` — ошибка сохранения |
| 5 | `+` `-` | `a + b > c` = `(a + b) > c` |
| 6 | `*` `/` `%` | `a + b * c` = `a + (b * c)` |
| 7 | унарные `-` `+` | `-a * b` = `(-a) * b` |

Порядок такой же, как в SQL и Python. Если сомневаетесь — ставьте скобки: `(a or b) and c`.

**Ключевые слова** `and`, `or`, `not`, `true`, `false`, `null` пишутся в любом регистре (`AND`, `True`, `NULL`).
Слово с точкой — всегда путь: `object.or`, `object.and`, `v1.null` — это поля, а не операторы. Слово без точки, после
которого нет `(`, — ошибка: пишите `object.amount`, а не `amount`.

### Значения и типы

- **Отсутствующее поле даёт пустую строку** (расчёт из-за этого не останавливается).
- `+` **складывает**, если оба операнда — числа строгого формата (число или текст вида `"10"`, `"-0.5"`, `" 3 "`), и **склеивает** в остальных случаях: `'10' + 5` → `15`, `object.name + 5` → `Deal5`. Текст `'1 234,56'` (пробел, запятая) и `'1e3'` числами не считаются — без `to_number()` получится склейка. `'' + 5` → `5` (склейка).
- `-` `*` `/` `%` требуют чисел. Пустое значение считается `0`. Текст, который не является числом, завершает шаг ошибкой: `Operator "*" requires numbers, got "abc"`.
- Деление или остаток от деления на ноль завершают шаг ошибкой: `Division by zero in expression`, `Modulo by zero in expression`. Остаток имеет знак делимого: `-7 % 3` → `-1`.
- **Арифметика точная десятичная** (bcmath), а не с плавающей точкой: `0.1 + 0.2` → `0.3`, `19.99 * 3` → `59.97`, `0.1 + 0.2 == 0.3` → `true`. Промежуточные результаты хранятся с точностью 10 знаков после запятой; деление округляется до 10 знаков, половина — от нуля (`1 / 3` → `0.3333333333`, `2 / 3` → `0.6666666667`).
- Тип результата: целое меньше 10¹⁵ — целое число (`9.0` → `9`, `object.amount * 0.9` при `500` → `450`); дробное, точно представимое 15 значащими цифрами, — дробное число (`10 / 4` → `2.5`); **иначе — текст с числом**, чтобы большие суммы не искажались: `'12345678901234567.89' + 0.01` → `'12345678901234567.9'`, `9007199254740993 + 0` → `'9007199254740993'`. Такое значение так же записывается в CRM и сравнивается условиями как число; в аудите `new_value` у него — строка.
- Число длиннее 100 цифр в целой части — ошибка `Number is too large` (в литерале — при сохранении процесса).
- Чтобы склеить числа как текст, используйте `concat`: `concat(object.code, object.number)`.
- Сравнения и логические операторы дают `true` или `false`. Если такое значение записывается в поле, оно сохраняется как булево.

### Правила сравнения

Правила применяются по порядку — срабатывает первое подходящее:

| № | Ситуация | Как сравнивается | Примеры |
|---|---|---|---|
| 1 | Пустые значения | `null` и `''` равны (отсутствующее поле — тоже `''`) | `object.missing == ''` → `true`, `null == ''` → `true` |
| 2 | `<` `<=` `>` `>=` и хотя бы один операнд пустой | всегда `false` | `object.missing > 5` → `false`, `object.missing < 5` → `false` |
| 3 | Один из операндов — `true` / `false` | второй приводится к булеву (`1`, `yes`, `да` → `true`; `0`, `no`, `нет` → `false`) | `'yes' == true` → `true`, `'abc' == true` → `false` |
| 4 | Оба операнда — числа строгого формата | точное десятичное сравнение (без погрешностей float) | `'100' == 100.00` → `true`, `'9' < '10'` → `true` |
| 5 | Оба — списки | `==` / `!=` поэлементно; `<` и другие — ошибка | `[1, 2] == ['1', '2']` → `true` |
| 6 | Всё остальное | как строки, побайтово; **регистр важен** | `'abc' == 'ABC'` → `false`, `'b' > 'a'` → `true` |

- **Число строгого формата** — цифры с необязательным знаком и десятичной точкой: `10`, `-3.5`, `.5`, `' 42 '` (пробелы по
  краям не мешают). Текст `'1 000'`, `'1 234,56'`, `'10 руб.'` числом **не** считается и сравнивается как строка: `'1 234,56' > 5` —
  строковое сравнение. Приведите такие значения к числу заранее (приведение типов в условиях или расчёт).
- Строка и число, если строка — не число: сравнение строковое (`'abc' > 5` → `true`, потому что `'a'` больше `'5'`).
- **Даты не распознаются автоматически.** Сравнивайте их в каноническом формате `ГГГГ-ММ-ДД` (или `ГГГГ-ММ-ДД ЧЧ:ММ:СС`) —
  тогда строковый порядок совпадает с хронологическим: `object.close_date < '2026-12-31'`. Даты вида `31.12.2026` так
  сравнивать нельзя.
- Регистр не учитывается только в ключевых словах и именах функций, но не в значениях. Для сравнения без учёта регистра:
  `lower(object.status) == 'active'`.
- Сравнение булева с неприводимым значением: `==` — `false`, `!=` — `true`, а `<` `>` … — ошибка `Cannot compare boolean with "abc"`.

### Истинность условий

`and`, `or`, `not`, условие `if()` и условия `ifs()` принимают только значения, однозначно понимаемые как «да» или «нет»:

| Считается истиной | Считается ложью |
|---|---|
| `true`, `1`, `yes`, `on`, `да` | `false`, `0`, `no`, `off`, `нет`, `''`, `null` (и отсутствующее поле) |

Любое другое значение завершает шаг ошибкой `Condition must be boolean, got "abc"` — опечатка в условии не превращается
молча в «ложь». Обычно в условие ставят сравнение: не `if(object.status, …)`, а `if(object.status == 'Active', …)`.

`and` и `or` вычисляют правую часть, только если она нужна (`false and …` → `false` без вычисления правой части), и
всегда возвращают `true` или `false`. `not object.missing` → `true`.

### Условные функции

Аргументы этих функций вычисляются **лениво**: невыбранная ветка не вычисляется, поэтому `if(true, 1, 1 / 0)` → `1` без ошибки
деления на ноль.

| Функция | Что возвращает | Пример |
|---|---|---|
| `if(cond, then[, else])` | `then`, если `cond` истинно, иначе `else` (без `else` — пустую строку) | `if(object.amount > 100000, 'VIP', 'Regular')` |
| `coalesce(a, b, …)` | первое непустое значение (не `null` и не `''`); если пусты все — пустую строку | `coalesce(object.phone_mobile, object.phone_work, v1.phone_office)` |
| `ifempty(a, default)` | `a`, если оно не пустое, иначе `default` | `ifempty(object.title, 'Без названия')` |
| `ifs(cond1, value1, cond2, value2, …[, default])` | значение первой пары с истинным условием; нечётный последний аргумент — значение по умолчанию; если ничего не подошло и умолчания нет — пустую строку | `ifs(object.amount > 1000000, 'A', object.amount > 100000, 'B', 'C')` |
| `switch(x, key1, value1, key2, value2, …[, default])` | значение для первого ключа, равного `x` (по правилам `==`); лишний последний аргумент — значение по умолчанию | `switch(object.rating, 'Hot', 'High', 'Warm', 'Medium', 'Low')` |

Примеры:

```text
concat('Категория ', ifs(object.amount > 1000000, 'A', object.amount > 100000, 'B', 'C'))
if(object.probability >= 50 and object.sales_stage != 'Closed Lost', 'В работе', 'Низкий приоритет')
concat('Звонить: ', coalesce(object.phone_mobile, object.phone_work, object.phone_other, 'нет телефона'))
switch(lower(object.lead_source), 'web site', 'Сайт', 'cold call', 'Холодный звонок', 'Другое')
if(object.amount > 0, round(object.discount / object.amount * 100, 1), 0)
```

`coalesce` и `ifempty` считают пустыми только `null` и `''`: `0`, `false` и `' '` (пробел) — значения.

### Функции

| Функция | Результат | Пример | Результат примера |
|---|---|---|---|
| `if(cond, then[, else])` | см. [Условные функции](#условные-функции) | `if(object.amount > 100, 'VIP', 'Regular')` | `VIP` |
| `coalesce(a, b, …)` | первое непустое значение | `coalesce(object.missing, object.name)` | `Deal` |
| `ifempty(a, default)` | `a` или значение по умолчанию | `ifempty(object.missing, 'нет')` | `нет` |
| `ifs(cond1, value1, …[, default])` | значение первой истинной пары | `ifs(object.amount > 1000, 'B', 'C')` | `C` |
| `switch(x, key1, value1, …[, default])` | значение для совпавшего ключа | `switch(object.name, 'Deal', 1, 0)` | `1` |
| `concat(a, b, …)` | все аргументы, склеенные в текст | `concat('Call back: ', object.name)` | `Call back: Ivan Petrov` |
| `upper(s)` | верхний регистр | `upper('hello')` | `HELLO` |
| `lower(s)` | нижний регистр | `lower('ABC')` | `abc` |
| `trim(s)` | текст без пробелов в начале и в конце | `trim('  x  ')` | `x` |
| `len(s)` | длина в символах | `len('Привет')` | `6` |
| `substr(s, start[, length])` | часть текста; `start` считается от 0, отрицательный — от конца | `substr('hello world', 0, 5)` | `hello` |
| `round(x[, digits])` | число, округлённое до `digits` знаков (по умолчанию 0) | `round(10.456, 2)` | `10.46` |
| `abs(x)` | модуль числа | `abs(-5)` | `5` |
| `min(a, b, …)` | наименьшее число | `min(object.amount, 1000)` | например, `500` |
| `max(a, b, …)` | наибольшее число | `max(object.amount, 0)` | например, `500` |
| `default(a, fallback)` | `a`, если оно не пустое, иначе `fallback` (как `ifempty`; удобно как фильтр шаблона) | `default(object.missing, '—')` | `—` |
| `number(x[, decimals[, dec_sep[, thousands_sep]]])` | синоним `number_format` | `number(1234.5, 2, ',', ' ')` | `1 234,50` |
| `capitalize(s)` | первая буква — заглавная | `capitalize('иван')` | `Иван` |
| `truncate(s, length[, suffix])` | текст не длиннее `length` символов вместе с `suffix` (по умолчанию `…`) | `truncate('Big deal', 5)` | `Big …` |
| `nl2br(s)` | переводы строк → `<br>` (для HTML-писем) | `nl2br(object.description)` | `line1<br>line2` |
| `json(v)` | значение в виде JSON | `json([1, 'a'])` | `[1,"a"]` |
| `urlencode(s)` | текст, закодированный для URL (RFC 3986) | `urlencode('a b&c')` | `a%20b%26c` |
| `join(list[, separator])` | элементы списка через `separator` (по умолчанию `, `); понимает массив, JSON-массив и multienum `^a^,^b^` | `join('^Banking^,^Retail^')` | `Banking, Retail` |

Текстовые функции работают с любым языком, в том числе с кириллицей. Число аргументов проверяется **при сохранении
процесса**: `substr(object.name)` не сохранится с ошибкой `Function "substr" expects 2..3 arguments, got 1`.
Числовые функции описаны в разделе [Числа](#числа).

Полный список функций с сигнатурами и описаниями отдаёт [`GET /api/dictionaries/functions`](../06-api-reference/endpoints.md#get-apidictionariesfunctions).
Разработчик может добавить новые функции: [Функции выражений](../07-developer-guide/extending/expression-functions.md).
Функции дат (`today`, `add_days`, `date_diff`, `format_date` …) описаны в разделе [Даты и время](#даты-и-время).

### Числа

Все числовые функции считают точно (десятично, см. [Значения и типы](#значения-и-типы)) и возвращают результат по
тем же правилам типа. Пустой аргумент (`''`, отсутствующее поле) считается `0`; нечисловой — ошибка выполнения
`Function "floor" requires a number, got "abc"`.

| Функция | Результат | Пример | Результат примера |
|---|---|---|---|
| `round(x[, digits])` | округление до `digits` знаков, **половина — от нуля** (2.5 → 3, −2.5 → −3); `digits` может быть отрицательным — до десятков, сотен … | `round(1.005, 2)`, `round(1250, -2)` | `1.01`, `1300` |
| `floor(x[, digits])` | округление вниз (к −∞) | `floor(-1.5)`, `floor(10.459, 2)` | `-2`, `10.45` |
| `ceil(x[, digits])` | округление вверх (к +∞) | `ceil(1.01)` | `2` |
| `trunc(x[, digits])` | отбрасывание дробной части (к нулю) | `trunc(-1.7)` | `-1` |
| `abs(x)` | модуль | `abs(-0.5)` | `0.5` |
| `sign(x)` | знак: `-1`, `0` или `1` | `sign(-3)` | `-1` |
| `min(a, b, …)`, `max(a, b, …)` | наименьшее / наибольшее; с одним аргументом-списком — по его элементам (пустой список → `''`) | `min([5, 2, 9])` | `2` |
| `pow(x, n)` | `x` в степени `n`; целая степень до 100 по модулю — точно, иначе через плавающую точку | `pow(1.1, 2)`, `pow(9, 0.5)` | `1.21`, `3` |
| `sqrt(x)` | квадратный корень, 10 знаков; от отрицательного — ошибка `sqrt() of a negative number` | `sqrt(2)` | `1.4142135624` |
| `percent(x, p)` | `p` процентов от `x` (`x * p / 100`) | `percent(200, 15)` | `30` |
| `to_number(s)` | число из текста: пробелы (в том числе неразрывные) убираются, `,` — десятичный разделитель, если нет `.`; пустое остаётся пустым (удобно с `coalesce`); `'1,234.56'` (оба разделителя) и `'abc'` — ошибка `Cannot convert "abc" to a number` | `to_number('1 234,56')` | `1234.56` |
| `to_int(s)` | целое из текста; дробная часть — ошибка `Cannot convert "1.5" to an integer`; пустое остаётся пустым | `to_int(' 42 ')` | `42` |
| `number_format(x[, decimals[, dec_sep[, thousands_sep]]])` | текст с разделителями; по умолчанию `decimals = 0`, `dec_sep = '.'`, `thousands_sep = ' '` (обычный пробел); округление — половина от нуля | `number_format(1234567.891, 2, ',', ' ')` | `1 234 567,89` |

Сценарии:

```
round(object.amount * 1.2, 2)                      сумма с НДС: 19.99 → 23.99, без 23.987999…
floor(object.amount / object.qty * 100) / 100      цена за единицу: 100 / 3 → 33.33
to_number(v1.price_text)                           '1 234,56' → 1234.56
number_format(object.amount, 2, ',', ' ')          1234567.891 → '1 234 567,89'
```

Изменения по сравнению с прежними версиями: `round(1.005, 2)` теперь `1.01` (раньше из-за погрешности float — `1`);
ошибки числовых функций — в формате `Function "round" requires a number, got "…"` (раньше
`Operator "round()" requires numbers, got "…"`). Если точность (`digits`, `decimals`) указана литералом, она должна быть
целой — иначе процесс не сохранится: `Function "round": precision must be an integer`,
`Function "number_format": decimals must be an integer`. Вычисленная дробная точность — ошибка выполнения.

### Даты и время

**Формат значений.** Функции дат возвращают строки в каноническом формате — их можно сразу записать в CRM
и правильно сравнивать как строки (`add_days(today(), 3) > '2026-10-18'`):

| Вид | Формат | Часовой пояс |
|---|---|---|
| дата | `Y-m-d` (`2026-10-16`) | календарный день, без пояса |
| дата-время | `Y-m-d H:i:s` (`2026-10-16 07:30:00`) | всегда UTC |

**Входные значения.** Аргумент-дата принимается в форматах `Y-m-d`, `Y-m-d H:i:s`, `Y-m-d H:i`, ISO 8601
(`2026-10-16T07:30:00Z`, `2026-10-16T10:30:00+03:00`, с долями секунды и без пояса), `d.m.Y`, `d.m.Y H:i`,
`d.m.Y H:i:s`.

- Дата-время **без смещения считается UTC** — так их отдаёт CRM. Значение со смещением переводится в UTC.
- Дата без времени там, где нужен момент (`add_hours`, `date_diff` в часах), — **полночь в `WPS_TIMEZONE`**.
- Пустое значение (`''`, `null`, отсутствующее поле, `0000-00-00`, `0000-00-00 00:00:00`) — результат `''`
  (кроме `now()` и `today()`). Пустота «протекает» дальше, как и отсутствующее поле.

**Часовой пояс.** `WPS_TIMEZONE` ([Конфигурация](../04-operations/configuration.md), по умолчанию `UTC`) — пояс
бизнес-логики, «local». В нём считаются `today()`, календарные дни, границы периодов, части даты и
`format_date()`. Функции с аргументом `tz` принимают `'local'` (= `WPS_TIMEZONE`), `'UTC'` или имя IANA
(`'Europe/Moscow'`).

**Функции.** Примеры — при `WPS_TIMEZONE=Europe/Moscow` и текущем моменте 2026-10-16 07:30 UTC.

| Функция | Результат | Пример | Результат примера |
|---|---|---|---|
| `now()` | текущий момент, UTC | `now()` | `2026-10-16 07:30:00` |
| `today([tz])` | сегодняшняя дата в поясе `tz` (по умолчанию local) | `today()` | `2026-10-16` |
| `date(value[, format])` | календарная дата; из даты-времени — день в local; `format` — формат PHP для нестандартного ввода | `date('2026-10-15 22:30:00')`, `date('16/10/2026', 'd/m/Y')` | `2026-10-16`, `2026-10-16` |
| `datetime(value[, format[, tz]])` | дата-время UTC; `tz` — в каком поясе записан ввод без смещения (по умолчанию UTC); дата без времени — полночь в `tz`, а без `tz` — в local | `datetime('2026-10-17 10:00', 'Y-m-d H:i', 'local')` | `2026-10-17 07:00:00` |
| `add_minutes(d, n)`, `add_hours(d, n)` | абсолютное время; дата становится датой-временем (от полуночи local) | `add_hours('2026-10-16', 2)` | `2026-10-15 23:00:00` |
| `add_days(d, n)`, `add_weeks(d, n)` | календарные дни; у даты-времени сохраняется местное время | `add_days(today(), 3)` | `2026-10-19` |
| `add_months(d, n)`, `add_years(d, n)` | месяцы с обрезкой конца месяца | `add_months('2026-01-31', 1)`, `add_years('2024-02-29', 1)` | `2026-02-28`, `2025-02-28` |
| `date_diff(from, to, unit)` | `to − from` целым числом единиц, дробная часть отбрасывается к нулю; `unit`: `minutes`, `hours`, `days`, `weeks`, `months`, `years` | `date_diff('2026-10-16', '2026-10-15', 'days')` | `-1` |
| `year(d[, tz])`, `month`, `day`, `hour`, `minute` | часть даты в local или `tz` | `hour('2026-10-16 07:30:00')`, `hour('2026-10-16 07:30:00', 'UTC')` | `10`, `7` |
| `weekday(d[, tz])` | день недели по ISO: 1 — понедельник … 7 — воскресенье | `weekday('2026-10-16')` | `5` |
| `week(d[, tz])`, `quarter(d[, tz])` | номер недели по ISO, квартал 1–4 | `week('2026-10-16')`, `quarter('2026-10-16')` | `42`, `4` |
| `start_of_day(d)`, `end_of_day(d)` | начало (`00:00:00`) / конец (`23:59:59`) дня | `end_of_day('2026-10-16 07:30:00')` | `2026-10-16 20:59:59` |
| `start_of_week(d)`, `end_of_week(d)` | понедельник / воскресенье | `start_of_week('2026-10-16')` | `2026-10-12` |
| `start_of_month(d)`, `end_of_month(d)` | первый / последний день месяца | `end_of_month('2026-02-10')` | `2026-02-28` |
| `start_of_quarter(d)`, `end_of_quarter(d)` | первый / последний день квартала | `end_of_quarter(today())` | `2026-12-31` |
| `start_of_year(d)`, `end_of_year(d)` | 1 января / 31 декабря | `start_of_year('2026-10-16')` | `2026-01-01` |
| `is_weekend(d[, tz])` | суббота или воскресенье (`true`/`false`) | `is_weekend('2026-10-16 22:00:00')` | `true` (в Москве уже суббота) |
| `format_date(d, format[, tz])` | текст по токенам PHP `DateTimeInterface::format`; дата-время показывается в local или `tz` | `format_date('2026-10-16 07:30:00', 'd.m.Y H:i')` | `16.10.2026 10:30` |
| `format_date_locale(d, pattern, locale[, tz])` | текст по шаблону ICU с названиями месяцев и дней на языке `locale` | `format_date_locale('2026-10-16', 'd MMMM y', 'ru')` | `16 октября 2026` |

Границы периодов сохраняют вид значения: для даты результат — дата, для даты-времени — граница в local,
переведённая в UTC. `format_date_locale` есть, только если в образе установлено расширение PHP `intl` (в
образе WPS оно есть); без него функции нет в справочнике и процесс с ней не сохранится.

**Переход на летнее время.** `add_days`, `add_weeks`, `add_months` у даты-времени работают с местным временем:
при `WPS_TIMEZONE=Europe/Berlin` `add_days('2026-03-28 06:00:00', 1)` = `2026-03-29 05:00:00` (07:00 по Берлину
и до, и после перевода часов). `add_hours`, `add_minutes` прибавляют абсолютное время: сутки 29.03.2026 в
Берлине — 23 часа (`date_diff(datetime('2026-03-29'), datetime('2026-03-30'), 'hours')` = `23`).

**`date_diff`.** `days` — разница календарных дней (дата-время сначала переводится в local):
`date_diff('2026-10-15 20:00:00', '2026-10-16 10:00:00', 'days')` = `1` (23:00 и 13:00 по Москве — разные дни),
а в часах — `14`. `weeks` — целые недели из дней. `months` и `years` — полные месяцы:
`date_diff('2026-01-31', '2026-02-28', 'months')` = `0`, `date_diff('2026-01-15', '2026-03-15', 'months')` = `2`.

**Типовые сценарии:**

```text
add_days(today(), 3)                                                         срок задачи через 3 дня
datetime(concat(add_days(today(), 1), ' 10:00'), 'Y-m-d H:i', 'local')       завтра в 10:00 по местному времени
date_diff(object.date_modified, now(), 'days')                               сколько дней сделка без движения
format_date(object.date_closed, 'd.m.Y')                                     дата для письма: 16.10.2026
end_of_quarter(today())                                                      конец квартала
```

**Рабочие дни не поддерживаются**: функций `add_workdays`, `workdays_between`, `is_workday` нет, производственный
календарь не учитывается (`is_weekend` проверяет только субботу и воскресенье). Если они нужны, разработчик
добавляет функцию через `registerFunction` — см. [Функции выражений](../07-developer-guide/extending/expression-functions.md#34-пример-рабочие-дни).

**Ошибки дат при сохранении:** `Function "date_diff": unit must be one of minutes, hours, days, weeks, months,
years, got "decades"` (единица-литерал), `Unknown timezone "Mars/Base"` (пояс-литерал), `Function "format_date":
format must not be empty`, `Unknown function "add_workdays"`. **Во время выполнения:** `Cannot parse date "abc" in
add_days()`, `Function "add_days": count must be an integer, got "x"` (дробное число тоже ошибка — дробные дни
задавайте через `add_hours`), `Unknown timezone "…" in today()` для вычисленного пояса,
`Cannot parse date "2026-02-30" in date()` для несуществующей даты.

### Лимиты

| Ограничение | Значение | Сообщение |
|---|---|---|
| Длина выражения | 4000 символов | `Expression is too long (max 4000 characters)` |
| Размер выражения | 500 узлов (чисел, путей, операторов, вызовов) | `Expression is too complex (max 500 nodes)` |
| Вложенность | 32 уровня скобок и вызовов | `Expression is nested too deeply (max 32 levels)` |
| Длина результата | 1 МБ | `Expression result is too long` |

Первые три проверяются при сохранении, длина результата — во время выполнения.

### Граничные случаи

| Выражение | Результат | Почему |
|---|---|---|
| `true + 1` | `true1` | `+` склеивает всё, что не является числами (поведение сохранено для совместимости) |
| `object.missing == ''` | `true` | отсутствующее поле — пустая строка, `null` = `''` |
| `object.missing > 5` | `false` | сравнение порядка с пустым значением всегда ложно |
| `not object.missing` | `true` | пустое значение — ложь |
| `'abc' > 5` | `true` | `'abc'` не число — сравнение строковое |
| `'1 234,56' > 5` | `false` | пробел и запятая — не числовой формат, сравниваются строки `'1…'` и `'5'` |
| `if(false, 1)` | `''` | без `else` возвращается пустая строка |
| `object.or == 1` | сравнение поля `or` | слово с точкой — путь, а не оператор |
| `if(object.status, 1, 0)` при `status = 'Active'` | ошибка `Condition must be boolean, got "Active"` | условие должно быть булевым |

### Примеры

Все примеры проверены на работающем WPS с объектом события `{ "id": "1", "name": "Deal", "amount": "500" }`:

| Выражение | Результат |
|---|---|
| `object.amount * 0.9` | `450` |
| `round(object.amount * 0.9, 2)` | `450` |
| `'10' + 5` | `15` |
| `object.name + 5` | `Deal5` |
| `object.missing * 2 + 1` | `1` |
| `10 / 4` | `2.5` |
| `0.1 + 0.2` | `0.3` |
| `round(object.amount * 1.2 + 0.005, 2)` | `600.01` |
| `7 % 3` | `1` |
| `substr(upper('hello world'), 0, 5)` | `HELLO` |
| `concat('Discount applied, new amount: ', object.amount)` | `Discount applied, new amount: 500` |
| `if(object.amount > 100, 'VIP', 'Regular')` | `VIP` |
| `object.amount == '500.00'` | `true` |
| `coalesce(object.missing, object.name)` | `Deal` |

### Ошибки

Проверяются при сохранении процесса (шаг с неверным выражением никогда не запустится):

| Сообщение | Причина |
|---|---|
| `Действие 1: укажите значение` / `Expression is required` | Пустое выражение |
| `Unknown function "foo"` | Такой функции нет |
| `Function "if" expects 2..3 arguments, got 1`, `Function "upper" expects 1 argument, got 0`, `Function "switch" expects at least 3 arguments, got 2` | Неверное число аргументов функции |
| `Comparison operators cannot be chained …` | Цепочка сравнений `1 < 2 < 3` — запишите `1 < 2 and 2 < 3` |
| `Unknown identifier "amount" (use object.<field> or <variable>.<field>) at position 0 in "amount * 2"` | Поле без префикса `object.` / переменной |
| `Unexpected ")" at position 8 in "round(1))"`, `Expected ")" at position …` | Непарные скобки или лишний оператор |
| `Unterminated string starting at position …` | Нет закрывающей кавычки |
| `Unexpected character "#" at position …` | Символ, которого нет в синтаксисе |
| `Expression is too long …`, `Expression is too complex …`, `Expression is nested too deeply …` | Превышен [лимит](#лимиты) |
| `Variable "v3" is not defined at this point` | Выражение использует переменную, которая не объявлена до этой строки |
| `Function "round": precision must be an integer`, `Function "number_format": decimals must be an integer` | Дробная точность-литерал |
| `Number is too large at position …` | Числовой литерал длиннее 100 цифр |

Проверяются во время выполнения (шаг завершается ошибкой, выполнение — со статусом **Ошибка**): операции над нечисловым
текстом, деление на ноль, небулево значение в условии (`Condition must be boolean, got "…"`), сравнение порядка для
списков (`Lists cannot be compared with "<"`) или булева значения с неприводимым (`Cannot compare boolean with "…"`),
слишком длинный результат (`Expression result is too long`), результат, который не является конечным числом
(`Expression result is not a finite number`), число длиннее 100 цифр (`Number is too large`), нечисловой аргумент
числовой функции (`Function "floor" requires a number, got "abc"`), неразбираемый текст в `to_number` / `to_int`
(`Cannot convert "abc" to a number`).

## Шаблон

Собирает текст из постоянных частей и подстановок — вместо цепочек `concat()`. Результат — всегда строка.

```text
Позвонить: {{ object.first_name }} {{ object.last_name }}
Сделка {{ object.name }} на {{ object.amount | number:2:',':' ' }} руб., срок {{ object.date_closed | format_date:'d.m.Y' }}
Ответственный: {{ owner.last_name | default:'не назначен' }}
Скидка: {{= if(object.amount > 100000, '10%', '0%') }}
```

Через API шаблон передаётся в `value` (поле `template` — синоним):

```json
{ "type": "modify", "target": "call.name", "change_type": "template",
  "value": "Позвонить: {{ object.first_name }} {{ object.last_name | upper | truncate:25 }}", "missing": "empty" }
```

### Синтаксис шаблона

| Конструкция | Что делает |
|---|---|
| `{{ path }}` | значение поля: `object.name`, `v1.address.city`; пробелы внутри скобок не важны |
| `{{ path \| f }}`, `{{ path \| f:a:b }}` | фильтры слева направо; `x \| f:a:b` вычисляется как функция `f(x, a, b)` |
| `{{ 'текст' }}`, `{{ 5 }}` | вместо пути можно подставить строку в кавычках или число |
| `{{= выражение }}` | любое выражение [Расчёта](#расчёт): `{{= coalesce(object.phone_mobile, object.phone_work, 'нет') }}`; фильтры внутри `{{= }}` не пишутся — используйте функции |
| `{{! комментарий }}` | ничего не выводит |
| `\{{` | литерал `{{` (подстановки нет) |
| `\\{{` | литерал `\`, за которым идёт подстановка |

- Аргумент фильтра — путь (`truncate:object.qty`), строка в `'…'` / `"…"` или число. Двоеточие и `|` внутри кавычек
  не разделяют аргументы: `format_date:'H:i'`.
- `}}` внутри строки выражения не закрывает тег: `{{= concat('}}', object.name) }}`.
- Одиночные `}}` в обычном тексте — просто текст (JSON-подобный текст `{"a":{"b":1}}` не ломает шаблон).
- Значение поля не обрабатывается как шаблон повторно: если в поле записано `{{ object.name }}`, оно подставится как
  есть.
- Внутри `{{ }}` — только путь, строка или число с фильтрами. Вычисления (`object.a * 2`) пишутся в `{{= }}`.

### Фильтры

Фильтр — это любая [функция выражений](#функции), первым аргументом которой становится значение: `upper`, `lower`,
`trim`, `substr`, `round`, `number`, `format_date`, `default`, `truncate`, `capitalize`, `join`, `json`, `urlencode`,
`nl2br` и остальные. Число аргументов фильтра проверяется при сохранении (`{{ x | truncate }}` →
`Template filter "truncate" expects 1..2 arguments, got 0`). Полный список с примерами отдаёт
[`GET /api/dictionaries/template-filters`](../06-api-reference/endpoints.md#get-apidictionariestemplate-filters).

| Шаблон | Результат (`object.amount = 1234567.891`, `object.date_closed = 2026-10-31`) |
|---|---|
| `{{ object.amount \| number:2:',':' ' }}` | `1 234 567,89` |
| `{{ object.date_closed \| format_date:'d.m.Y' }}` | `31.10.2026` |
| `{{ '  abc ' \| trim \| upper }}` | `ABC` |
| `{{ object.name \| truncate:5 }}` при `name = Big deal` | `Big …` |
| `{{ object.industries \| join }}` при `^Banking^,^Retail^` | `Banking, Retail` |

### Отсутствующие значения

Значение **отсутствует**, если переменной нет, она пустая (`null`) или в ней нет такого поля. Поле, которое есть, но
содержит `''` или `null`, — **не** отсутствует: подставляется пустая строка.

Что делать с отсутствующим значением, задаёт параметр `missing` строки:

| `missing` | Результат |
|---|---|
| `empty` (по умолчанию) | пустая строка; путь попадает в `result_data.missing` шага (видно в аудите) |
| `error` | шаг завершается ошибкой `Template references missing value "v1.email"` |
| `keep` | тег остаётся в тексте как есть (`{{ object.none }}`) — удобно для отладки |

Фильтр `default` срабатывает и на пустое, и на отсутствующее значение: `{{ object.none | default:'—' }}` → `—`, а при
`missing: error` строка с `default` ошибкой не завершается.

### Приведение к строке

`null` → пустая строка, `true` / `false` → `true` / `false`, дробное число — без хвостовых нулей (`90.0` → `90`), список
или объект → JSON (`["a","b"]`). Multienum (`^a^,^b^`) подставляется как есть — фильтр `join` превращает его в текст.

### Ограничения и ошибки шаблона

| Ограничение / ошибка | Когда | Сообщение |
|---|---|---|
| Длина шаблона 64 КБ | при сохранении | `Template is too long (max 65536 characters)` |
| Результат больше 1 МБ | при выполнении | `Template result is too long` |
| Незакрытый тег | при сохранении | `Unclosed "{{" at position 7` (позиция — в символах) |
| Пустой тег `{{ }}` | при сохранении | `Empty template tag at position 2` |
| Пустое выражение `{{= }}` | при сохранении | `Empty expression in template tag at position …` |
| Неизвестный фильтр | при сохранении | `Unknown template filter "foo"` |
| Неверное число аргументов фильтра | при сохранении | `Template filter "truncate" expects 1..2 arguments, got 0` |
| Выражение вместо пути в `{{ }}` | при сохранении | `Invalid value "object.a * 2" in template tag …` |
| Ошибка в `{{= }}` | при сохранении | сообщение разбора выражения, например `Unexpected end of expression …` |
| Фильтр `raw` | при сохранении | `Template filter "raw" is not allowed here` (в `modify` запрещён) |
| Не объявленная переменная | при сохранении | `Variable "v9" is not defined at this point` |
| Подстановка целой переменной `{{ object }}` | при сохранении | `"object" must point to a field, e.g. object.name` |
| Неверный `missing` | при сохранении | `Must be one of: empty, error, keep` (поле `missing`) |
| Шаблон — не строка | при сохранении | `Template must be a string` |
| Ошибка функции-фильтра | при выполнении | как в Расчёте: `Function "number_format" requires a number, got "Big deal"` |

Ошибки подстановки во время выполнения считает метрика
[`wps_template_render_errors_total`](../04-operations/monitoring.md).

## Сдвиг даты

Тип `date_shift` («Сдвиг даты») считает дату от базы со сдвигом — без формул. Это структурированная форма того, что в
**Расчёте** пишется функциями `add_days()`, `add_months()` и т. п. (см. [Даты и время](#даты-и-время)): обе формы
используют один и тот же код, поэтому результаты совпадают. `date_shift` удобнее для простых сроков и будущего
интерфейса, `calculate` — когда нужна логика (`if`, `date_diff`, форматирование).

```json
{ "type": "modify", "target": "task.date_due", "change_type": "date_shift",
  "base": "now", "shift": [ { "amount": 2, "unit": "day" } ], "set_time": "18:00" }
```

| Поле | Значения | По умолчанию |
|---|---|---|
| `base` | `now` — текущий момент; `today` — сегодняшняя дата в `WPS_TIMEZONE`; путь к полю (`object.date_closed`, `v1.x`) | `now` |
| `base_cast` | как разбирать поле-базу: `"date"` / `"datetime"` или объект `{"type": "date"\|"datetime", "format": "d.m.Y H:i", "timezone": "Europe/Moscow"}` (`format` — строка или список форматов PHP, `timezone` — в каком поясе записано время без смещения) | формат определяется сам (как в функциях дат), дата-время без смещения — UTC |
| `shift` | список `{"amount", "unit"}`, применяется по порядку; один объект `{"amount": 3, "unit": "day"}`; короткая строка `"+2 day"`, `"-30 days"`, `"+1 week -2 day +30 minute"` | без сдвига |
| `unit` | `minute`, `hour`, `day`, `week`, `month`, `year` (допустимо множественное число: `days`) | — |
| `amount` | целое (можно отрицательное) или путь к полю с целым числом (`"object.days"`); `\|amount\| ≤ 100000` | — |
| `set_time` | `HH:MM` — время суток после сдвига, по `WPS_TIMEZONE` | не менять |
| `result` | `date` → `Y-m-d` (день в `WPS_TIMEZONE`), `datetime` → `Y-m-d H:i:s` в UTC | вид получившегося значения (ниже) |
| `on_missing` | если поля-базы нет, оно пустое или `0000-00-00`: `null` — результат `null` (поле очищается), `error` — шаг падает, `now` — взять текущий момент | `null` |

Список единиц — в справочнике [`GET /api/dictionaries/date-units`](../06-api-reference/endpoints.md#get-apidictionariesdate-units).

**Как считается.**

- База `now` — дата-время; `today` — дата; поле — дата или дата-время по своему значению (или по `base_cast`).
- `minute`, `hour` — абсолютное время: через переход на летнее время `+24 hour` даёт другое местное время.
  Дата после сдвига в часах становится датой-временем (от полуночи по `WPS_TIMEZONE`).
- `day`, `week`, `month`, `year` — календарные единицы по местному времени (`WPS_TIMEZONE`): 09:00 остаётся 09:00
  и после перехода на летнее время. Месяцы обрезаются по концу месяца: 31.01 + 1 month = 28.02 (29.02 в високосный год),
  29.02 + 1 year = 28.02.
- `set_time` ставит местное время и делает результат датой-временем. Если такого времени нет (оно попало в «дыру»
  перехода на летнее время), берётся следующее существующее: 02:30 в ночь перехода в Берлине → 03:30.
- `result` по умолчанию — вид получившегося значения: `today` или поле-дата без `set_time` и без сдвига в часах → дата;
  `now`, поле с временем, сдвиг в минутах/часах или `set_time` → дата-время в UTC. Явный `result: date` у даты-времени
  берёт день по `WPS_TIMEZONE`, `result: datetime` у даты — полночь по `WPS_TIMEZONE`.

**Аудит.** В `result_data` шага, кроме `old_value` / `new_value`: `base` (база в каноническом виде), `shifts`
(применённые сдвиги с числами, подставленными из полей: `[{"amount": 5, "unit": "day"}]`) и `missing_base`
(`true`, если поле-базы не было).

**Рабочих дней нет.** Сдвиг считается только в календарных единицах; производственный календарь, праздники и
рабочие часы не учитываются. Чтобы добавить, например, `workday`, нужен новый вариант `DateUnit` и метод
`DateMath` (см. [Свои функции выражений](../07-developer-guide/extending/expression-functions.md)).

### Сценарии

| Задача | Настройка | Результат (`WPS_TIMEZONE = Europe/Moscow`, сейчас 16.10.2026 10:30 МСК) |
|---|---|---|
| Срок задачи — через 2 дня в 18:00 | `{"base": "now", "shift": "+2 day", "set_time": "18:00"}` | `2026-10-18 15:00:00` (UTC) |
| Звонок завтра в 10:00 | `{"base": "today", "shift": "+1 day", "set_time": "10:00"}` | `2026-10-17 07:00:00` |
| Напоминание за 30 дней до окончания договора | `{"base": "object.contract_end", "shift": "-30 day"}` при `2026-12-01` | `2026-11-01` |
| Следующий контакт через месяц | `{"base": "object.date_closed", "shift": "+1 month"}` при `2026-01-31` | `2026-02-28` |
| Срок ответа по обращению — 8 часов | `{"base": "now", "shift": "+8 hour"}` | `2026-10-16 15:30:00` |

То же через **Расчёт**: `datetime(concat(add_days(today(), 2), ' 18:00'), 'Y-m-d H:i', 'local')`,
`add_days(object.contract_end, -30)`, `add_months(object.date_closed, 1)`, `add_hours(now(), 8)`.

### Ошибки сдвига даты

| Ситуация | Когда | Сообщение |
|---|---|---|
| `base` — не `now` / `today` / путь | при сохранении | `Base must be "now", "today" or a field path` или ошибка пути (`"yesterday" must point to a field …`) |
| База — необъявленная переменная | при сохранении | `Variable "v9" is not defined at this point` |
| Неверный `base_cast` | при сохранении | `Base cast must be "date" or "datetime"`; опции — как у `cast` (`Unknown timezone "Mars/Base"` в `base_cast.timezone`) |
| `shift` не список и не строка вида `"+2 day"` | при сохранении | `Shift must be a list of {amount, unit} or a string like "+2 day"` |
| Неизвестная единица (в т. ч. `workday`) | при сохранении | `Unit must be one of: minute, hour, day, week, month, year` |
| `amount` дробное или текст | при сохранении | `Amount must be an integer or a field path` |
| `\|amount\| > 100000` | при сохранении | `Amount is out of range` |
| `set_time` не `HH:MM` (`9:00`, `24:00`) | при сохранении | `Time must be HH:MM` |
| Неверный `result` / `on_missing` | при сохранении | `Result must be "date" or "datetime"` / `Must be one of: null, error, now` |
| Поле-база не разбирается | при выполнении | `date_shift: cannot parse "abc" as datetime` (или `as date` при `base_cast: date`) |
| `amount` из поля не целое | при выполнении | `date_shift: amount must be an integer, got "1.5"` |
| Нет базы при `on_missing: error` | при выполнении | `date_shift: base "object.contract_end" has no value` |

## Увеличить / уменьшить на

Типы `increment` («Увеличить на») и `decrement` («Уменьшить на») прибавляют к текущему значению поля `target` шаг или
вычитают его — счётчики касаний, остатки, баллы без выражения `x + 1`.

```json
{ "type": "modify", "target": "object.touches_c", "change_type": "increment" }
{ "type": "modify", "target": "object.balance_c", "change_type": "decrement", "value": "150,75", "cast": "decimal", "scale": 2 }
{ "type": "modify", "target": "object.score_c", "change_type": "increment", "value_type": "from_object_field", "value": "v1.bonus" }
```

| Поле | Значения | По умолчанию |
|---|---|---|
| `value` | шаг — число (`1`, `"1,5"`) или путь при `value_type: from_object_field` | `1` |
| `cast` | `int` или `decimal` — вид результата | целое, если текущее значение и шаг целые, иначе десятичное |
| `scale` | знаков после запятой, `0..10` | без округления |
| `on_invalid` | текущее значение не число: `error` — шаг падает, `reset` — считать от 0 | `error` |

- Отсутствующее или пустое текущее значение считается **0**: первый `increment` даёт `1`.
- Дробные числа — десятичная арифметика без потери копеек (`80 + 0.25 = 80.25`).
- Значение берётся **из контекста выполнения** (события или переменной), а не перечитывается из CRM, и запись
  `PUT` не атомарна: если два процесса одновременно увеличат одно поле, одно увеличение может потеряться. Для точных
  счётчиков считайте значение агрегатом по записям.
- Ошибки: `Step must be a number`, `Cast must be "int" or "decimal"`, `Scale must be an integer from 0 to 10`,
  `Must be "error" or "reset"`; при выполнении — `increment: current value "abc" of object.x is not a number`.

## Очистить

Тип `clear` («Очистить») делает поле пустым:

```json
{ "type": "modify", "target": "object.sic_code", "change_type": "clear" }
{ "type": "modify", "target": "object.reason_c", "change_type": "clear", "empty": "null" }
```

`empty` — `""` (по умолчанию, пустая строка — плагин SuiteCRM надёжно пишет её в поле любого типа) или `"null"` (для
CRM, где разница важна; плагин SuiteCRM тоже очищает поле). Другое значение — `Must be "" or "null"`.

## Дописать в конец / в начало, удалить из списка

Типы `append` («Дописать в конец»), `prepend` («Дописать в начало») и `remove` («Удалить из списка») дописывают текст к
полю или добавляют и удаляют элементы списка (мультисписка).

**Текст** (`mode: "text"`, по умолчанию) — к текущему значению добавляется [шаблон](#шаблон) `value` (или значение поля при
`value_type: from_object_field`):

```json
{ "type": "modify", "target": "object.description", "change_type": "append",
  "value": "{{ now() | format_date:'d.m.Y' }}: тикер {{ object.ticker_symbol }}", "separator": "; ", "max_length": 2000 }
```

- `separator` ставится только между старым и новым значением: к пустому полю разделитель не добавляется.
- Пустое новое значение оставляет поле как было.
- `max_length` — предел длины результата: `append` сохраняет **конец** (самые новые записи), `prepend` — начало.

**Список** (`mode: "list"`) — поле разбирается как список, элементы `value` добавляются или удаляются:

```json
{ "type": "modify", "target": "object.template_ddown_c", "change_type": "append", "mode": "list",
  "value": "vip", "list": { "separator": ",", "wrapper": "^" } }
{ "type": "modify", "target": "object.template_ddown_c", "change_type": "remove", "mode": "list",
  "value": "^cold^,^test^", "list": { "separator": ",", "wrapper": "^" } }
```

- `list` — формат хранения: `separator` (по умолчанию `,`, 1–5 символов) и `wrapper` (например `^` для мультисписка
  SuiteCRM `^a^,^b^`). Значение `value` разбирается тем же форматом, поэтому можно добавить несколько элементов сразу.
- `unique` (по умолчанию `true`) — не добавлять элементы, которые уже есть.
- Результат записывается в том же формате (`^vip^,^gold^`); если поле было массивом (например, из ответа HTTP), массив
  и остаётся. Все элементы удалены — пустая строка `''`.
- `remove` работает **только** с `mode: "list"`: `"remove" works only with mode "list"`.
- Ошибки: `Value is required`, `Mode must be "text" or "list"`, `Must be an object {"separator": ..., "wrapper": ...}`,
  `Separator must be 1-5 characters`, `Wrapper must be up to 5 characters`, `Must be a positive integer` (`max_length`).

## По таблице соответствия

Тип `map` («По таблице соответствия») переводит значение поля `source` по таблице: отрасль → рейтинг, сумма → категория,
код страны → регион.

**Точное соответствие** (`mode: "exact"`, по умолчанию):

```json
{ "type": "modify", "target": "object.rating", "change_type": "map", "source": "object.industry",
  "map": { "Banking": "Hot", "Technology": "Warm", "": "Не указана" }, "default": "Cold",
  "cast": "string", "cast_options": { "case_sensitive": false } }
```

- Ключи `map` приводятся тем же `cast` / `cast_options`, что и значение `source` (регистр — `case_sensitive`, как в
  условиях). Ключ `""` срабатывает для пустого или отсутствующего значения. Ключи, совпадающие после приведения
  (`"100"` и `"100.0"` при `decimal`), — ошибка сохранения.

**Диапазоны** (`mode: "ranges"`, `cast` обязателен: `int`, `decimal`, `date`, `datetime`):

```json
{ "type": "modify", "target": "object.priority_c", "change_type": "map", "source": "object.amount", "mode": "ranges",
  "cast": "decimal", "ranges": [ { "lt": 10000, "value": "Low" }, { "lt": 100000, "value": "Medium" }, { "lte": 1000000, "value": "High" } ],
  "default": "Strategic" }
```

- Диапазоны проверяются по порядку, срабатывает первый: `lt` — строго меньше границы, `lte` — меньше или равно. Границы
  должны идти по возрастанию.

**Общее.**

- `value_template: true` — значения таблицы и `default` — [шаблоны](#шаблон): `"Клиент {{ object.name }}"`.
- Нет совпадения — `on_no_match`: `default` (значение `default`; так по умолчанию, если `default` задан), `keep` (поле не
  меняется; по умолчанию без `default`), `null`, `error` (шаг падает: `map: no match for "Other" in object.industry`).
- Ошибки сохранения: `Mode must be "exact" or "ranges"`, `Map must be a non-empty object`, `Too many entries (max 500)`,
  `Key "x" cannot be cast to decimal`, `Keys "100" and "100.0" are equal after cast`,
  `Mode "ranges" requires cast: int, decimal, date or datetime`, `Ranges must be a non-empty list`,
  `Range must have exactly one of "lt", "lte"`, `Value is required`, `Bound is not a valid decimal`,
  `Ranges must be in ascending order`, `Must be one of: default, keep, null, error`, `Default value is required`.

**Пример: карточка контрагента.** При смене тикера контрагента — счётчик, история, очистка и рейтинг по отрасли:

```json
{ "type": "modify", "target": "object.employees", "change_type": "increment" }
{ "type": "modify", "target": "object.description", "change_type": "append", "value": "тикер {{ object.ticker_symbol }}", "separator": "; " }
{ "type": "modify", "target": "object.sic_code", "change_type": "clear" }
{ "type": "modify", "target": "object.rating", "change_type": "map", "source": "object.industry",
  "map": { "Banking": "Hot", "Technology": "Warm" }, "default": "Cold", "cast": "string", "cast_options": { "case_sensitive": false } }
```

Результат на SuiteCRM 8 (кейс `.tehnical/suiteCRM8/processes/cases/5.1.3-change-types.json`): у контрагента с 4
сотрудниками, описанием «создан», `sic_code` 6021 и отраслью Banking после смены тикера на WPS1 — 5, «создан; тикер
WPS1», пустой `sic_code`, рейтинг Hot; после смены отрасли на Other и тикера на WPS2 — 6, «создан; тикер WPS1; тикер
WPS2», рейтинг Cold.

## Агрегат по записям

Тип `aggregate` («Агрегат по записям») считает **количество, сумму, среднее, минимум или максимум по записям CRM** и
пишет результат в поле: «число открытых задач контрагента», «сумма сделок», «дата последнего звонка». Это аналог
вычисляемых полей-сводок (roll-up) — без отдельного поиска и цикла.

```json
{ "type": "modify", "target": "object.annual_revenue", "change_type": "aggregate",
  "function": "sum", "field": "amount",
  "source": { "relationship": { "module": "Accounts", "id": "object.id", "link": "opportunities" } } }
```

| Поле | Значения | По умолчанию |
|---|---|---|
| `function` | `count`, `count_distinct`, `sum`, `avg`, `min`, `max` (справочник [`GET /api/dictionaries/aggregate-functions`](../06-api-reference/endpoints.md#get-apidictionariesaggregate-functions)) | — |
| `field` | Поле записей, по которому считается функция; для `count` не нужно (считаются записи) | — |
| `cast` | Как приводить значения: для `sum` / `avg` — `int` или `decimal`; для `min` / `max` обязательно — `int`, `decimal`, `date`, `datetime` или `string`; для `count_distinct` — те же или без приведения. Опции — `cast_options`, как у условий | `decimal` для `sum` / `avg` |
| `scale` | Знаков после запятой у `sum` / `avg`, `0..10` | `2` для `avg`, без округления для `sum` |
| `source` | **Ровно одно** из двух: `{"module": "Tasks", "filter": [...]}` — записи модуля по фильтру (формат и операторы — как у [Найти записи](actions.md#найти-записи), фильтр обязателен); `{"relationship": {"module": "Accounts", "id": "object.id", "link": "opportunities"}}` — записи, связанные с записью `id` (путь к id) по link-полю | — |
| `limit` | Наибольшее число читаемых записей, `1..AGGREGATE_MAX_RECORDS` | `1000` |
| `on_limit` | Записей больше `limit`: `error` — шаг падает; `partial` — результат по первым `limit` записям (в аудите `truncated: true`) | `error` |
| `empty_result` | Результат, если записей нет (или у всех пустое поле) | `0` для `count`, `count_distinct`, `sum`; `null` для `avg`, `min`, `max` |

Тип работает везде, где работают типы изменения: в `modify`, в [`set_variable`](actions.md#записать-в-переменную-процесса)
(несколько агрегатов в одной переменной) и в правилах [`update_records`](actions.md#изменить-записи-списка).

**Как считается.**

1. **Источник `module` + `filter`.** Фильтр переводится в запрос контракта CRM 2.0. Если значение фильтра из записи
   пустое (например, `object.account_id` не заполнен), **запроса нет**: результат — `empty_result`, в аудите
   `skipped_reason`. Иначе `account_id = ''` посчитал бы все записи без контрагента.
2. **`count` без `field` по фильтру** — один запрос: число берётся из `meta.total` CRM (возможность `count`), записи
   не читаются.
3. Остальные случаи: WPS читает записи страницами по 100 (только `id` и `field`) и сворачивает их сам. Записей больше
   `limit` — по `on_limit`.
4. **Источник `relationship`** — связанные записи читаются целиком (фильтра нет); пустой `id` — результат
   `empty_result` без запроса. Нужна возможность CRM `relationships`.
5. Пустые значения (`null`, `''`) пропускаются. Значение, которое не приводится по `cast`, — ошибка шага с id записи:
   `aggregate: value "abc" of Opportunities.amount (id …) is not a decimal`.
6. Суммы и среднее — десятичная арифметика без потери копеек (`1000 + 2500.50 = 3500.5`); числа возвращаются числами.
   `min` / `max` дат — в формате хранения CRM: дата `Y-m-d`, дата-время `Y-m-d H:i:s` в UTC.
7. **Результат не транзакционный**: пока WPS читает страницы, записи в CRM могут измениться. Для сводок это обычно
   неважно; для денег, где важна точность на момент, сверяйте итог отдельно.

**Аудит.** В `result_data` шага, кроме `old_value` / `new_value`: `function`, `module` (и `link` для связи),
`records_scanned` (сколько записей прочитано), `pages`, `truncated`, `total` (если число взято из `meta.total`),
`skipped_reason` (запроса не было). Для `set_variable` детали — у каждого поля.

**Нагрузка на CRM.** Каждый агрегат — отдельный запрос (или несколько страниц) при каждом выполнении процесса. Узкие
фильтры, `count` без `field` и разумный `limit` её ограничивают; общий предел — `AGGREGATE_MAX_RECORDS` (см.
[Интеграция с CRM](../04-operations/crm-integration.md)).

    "source": { "relationship": { "module": "Accounts", "id": "object.id", "link": "opportunities" } } },
  { "name": "total", "change_type": "aggregate", "function": "sum", "field": "amount",

    "source": { "module": "Tasks", "filter": [
      { "field": "parent_id", "operator": "equals", "value_type": "from_object_field", "value": "object.id" },
      { "field": "status", "operator": "not_in", "value": ["Completed", "Deferred"] } ] } },

Результат на SuiteCRM 8 (кейс `.tehnical/suiteCRM8/processes/cases/5.1.7-aggregate.json`): у контрагента 3 связанные
сделки на 1000, 2500.50 и 500 → `deals = 3`, `total = 4000.5`, `avg = 1333.5` (`records_scanned = 3`); 2 открытые

### Ошибки агрегата

| Ситуация | Когда | Сообщение (поле) |
|---|---|---|
| Неизвестная функция | при сохранении | `Function must be one of: count, count_distinct, sum, avg, min, max` (`…function`) |
| Нет `field` у функции кроме `count`, неверное имя поля | при сохранении | `Field is required for "sum"`, `Invalid field name` (`…field`) |
| Неподходящий `cast` | при сохранении | `Function "sum" requires cast: int or decimal`, `Function "max" requires cast: int, decimal, date, datetime or string`, `Cast must be one of: …` (`…cast`) |
| Неверный `scale` | при сохранении | `Scale must be an integer between 0 and 10` (`…scale`) |
| Нет источника или указаны оба | при сохранении | `Specify either "module" with "filter" or "relationship"` (`…source`) |
| Агрегат по всему модулю | при сохранении | `Filter is required (aggregating a whole module is not allowed)` (`…source.filter`) |
| Ошибки строк фильтра | при сохранении | те же, что у «Найти записи» (`…source.filter[j]…`) |
| Неверная связь | при сохранении | `Invalid CRM module`, `Link name is required (e.g. contacts)`, ошибка пути `id` (`…source.relationship.*`) |
| Неверные `limit` / `on_limit` | при сохранении | `Limit must be between 1 and 5000`, `Must be "error" or "partial"` |
| Записей больше `limit` при `on_limit: error` | при выполнении | `aggregate: more than 1000 records of Opportunities; narrow the filter or set "on_limit": "partial"` |
| Значение не приводится | при выполнении | `aggregate: value "abc" of Opportunities.amount (id …) is not a decimal` |

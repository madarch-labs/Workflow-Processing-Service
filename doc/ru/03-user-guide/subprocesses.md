# Ведомые процессы

Как разбить сценарий на родительский и ведомые процессы, что получает ведомый процесс и как он запускается.

<!-- lang-switch -->
[🇬🇧 English](../../en/03-user-guide/subprocesses.md) | 🇷🇺 Русский
<!-- /lang-switch -->

## Когда нужен ведомый процесс

**Ведомый процесс** (`is_child: true`) никогда не запускается событием CRM напрямую: при обработке события подбираются
только активные **процессы верхнего уровня**. Ведомый процесс выполняется, только когда его запускает другой процесс
действием **Запустить следующий процесс** (`start_process`). Ведомые процессы удобны, чтобы:

- использовать одну цепочку действий из нескольких родительских процессов;
- выполнять независимые ветки параллельно (каждый ведомый процесс работает в своей корутине);
- не перегружать длинный родительский процесс.

## Создание ведомого процесса

1. Откройте **Создать процесс**.
2. В поле **Тип процесса** выберите **Ведомый процесс**.
3. Выберите **Тип объекта (object.type)**. Для ведомого процесса это справочная информация: он работает с объектом
   события родителя, какого бы типа тот ни был.
4. Настройте условия, предзагрузку и действия как обычно и сохраните процесс.

В ведомом процессе можно ссылаться на переменные, которые в нём не объявлены (например, `v1.name`, загруженную
родителем): валидатор разрешает неизвестные переменные, потому что ведомый процесс наследует все переменные родителя.

В карточке ведомого процесса есть поле **Запускается из** со ссылками на все процессы, которые его запускают.

![Карточка ведомого процесса: «Запускается из» указывает на родителя, четыре действия создают и сохраняют задачу](../../images/screenshots/ru/18-process-detail-child.png)

*Ведомый процесс #4 «Create follow-up task»: запускается из процесса для лидов и создаёт новую запись `Tasks`.*

## Запуск ведомого процесса из родительского

1. Откройте родительский процесс на редактирование.
2. В **Блоке 2. Действия** раскройте **Запустить следующий процесс**.
3. Нажмите **Добавить процесс** и выберите ведомый процесс в списке **Выберите ведомый процесс**. В списке только
   процессы с типом **Ведомый процесс**, неактивные помечены **неактивен**. Кнопка обновления перезагружает список
   (**Обновить список ведомых процессов**), ссылка **открыть** открывает выбранный процесс.
4. Сохраните родительский процесс.

![Строка «Запустить следующий процесс» с ведомым процессом #4](../../images/screenshots/ru/08-process-edit-start-process.png)

*Родительский процесс #6: два условия по «И» и одна строка запуска следующего процесса.*

В JSON действие хранится так:

```json
{ "type": "start_process", "process_id": 4 }
```

или, если в одном шаге запускается несколько процессов:

```json
{ "type": "start_process", "process_ids": [4, 7] }
```

`4` и `7` здесь — id **ваших** ведомых процессов (число после `#` в карточке процесса).

## Что получает ведомый процесс

| | Поведение |
|---|---|
| Событие | То же событие, что у родителя (`event_id`, `object`). Переменная `object` содержит значения **после** изменений родителя. |
| Переменные | Все переменные родителя на момент шага `start_process` (`v1`, `task`, …). |
| Несохранённые изменения | Не наследуются: в ведомом процессе изменённых полей нет, поэтому `save_object` в нём отправляет только поля, изменённые самим ведомым процессом. |
| Источник запуска | `child` (в журнале — **Дочерний**), `parent_execution_id` указывает на выполнение родителя. |
| Условия | Проверяются собственные условия ведомого процесса; если они не выполнены, он не запускается. |
| Однократный запуск | Применяется к записи из события родителя (`object.id`). |

## Как он выполняется

- **Асинхронно.** Родитель не ждёт ведомый процесс: шаг `start_process` завершается сразу после запуска, и родитель
  переходит к следующему действию. Ошибка ведомого процесса не приводит к ошибке родителя.
- **Неактивный ведомый процесс пропускается.** Шаг остаётся успешным, а в его результате у процесса указано
  `"status": "skipped", "reason": "Process is inactive"`.
- **Ограничение глубины.** Цепочка «родитель → ведомый → следующий ведомый …» ограничена параметром `MAX_CHILD_DEPTH`
  (по умолчанию 10). При превышении шаг завершается ошибкой `Maximum child process depth (10) exceeded`.
- **Один раз на шаг.** Если шаг родителя выполняется повторно после восстановления от сбоя, тот же ведомый процесс
  второй раз не запускается.

Результат шага `start_process` в аудите:

```json
{
  "children": [
    { "process_id": 18, "name": "Inactive child", "status": "skipped", "reason": "Process is inactive" },
    { "process_id": 16, "name": "Notify manager", "status": "started" }
  ]
}
```

На странице выполнения родителя ведомые процессы перечислены в таблице **Дочерние выполнения**. Нажмите на id, чтобы
открыть выполнение ведомого процесса.

![Выполнение родителя: шаг start_process и таблица «Дочерние выполнения»](../../images/screenshots/ru/13-execution-detail-parent-child.png)

*Выполнение процесса #6: один шаг `start_process` и под ним завершённое дочернее выполнение.*

## Правила проверки

| Ситуация | Результат при сохранении |
|---|---|
| Выбранный процесс не ведомый | `422 VALIDATION_ERROR`: `Process 1 "…" is not a child process` |
| Процесса не существует | `422 VALIDATION_ERROR`: `Process 42 not found` |
| Процесс запускает сам себя | `422 VALIDATION_ERROR`: `A process cannot start itself` |
| Цикл запуска, например A → B → A | `422 CYCLE_DETECTED`, в интерфейсе — **Обнаружен цикл запуска процессов** и цепочка процессов |
| Удаление ведомого процесса, на который есть ссылки | `409 PROCESS_IN_USE`: **Процесс используется другими процессами (start_process) и не может быть удалён** |

Пример ошибки цикла:

```json
{
  "code": "CYCLE_DETECTED",
  "message": "Process launch cycle detected: Cycle A → Cycle B → Cycle A",
  "details": { "path": [ { "id": 16, "name": "Cycle A" }, { "id": 17, "name": "Cycle B" }, { "id": 16, "name": "Cycle A" } ] }
}
```

> **Примечание**
> Ведомый процесс можно запустить вручную из его карточки, как любой другой процесс (см. [Ручной запуск и сброс](manual-run-and-reset.md)).
> В этом случае родителя нет: источник запуска — `manual`, унаследованных переменных нет.

# Первый процесс

Пошаговое руководство: собираем в интерфейсе процесс «Активная сделка → пометить контрагента как VIP» и проверяем его
тестовым событием из мока.

<!-- lang-switch -->
[🇬🇧 English](../../en/02-getting-started/first-process.md) | 🇷🇺 Русский
<!-- /lang-switch -->

## Что строим

Когда сделка (`Deals`) сохраняется со статусом `Active`, WPS загружает из CRM контрагента сделки, ставит его полю `rating`
значение `VIP` и сохраняет контрагента обратно в CRM.

Используем четыре строительных блока:

| Блок | Настройка |
|---|---|
| Условие | `object.status` **Равен** значению `Active` |
| Предзагрузка | переменная `v1` ← модуль `Accounts` по полю поиска `id` = `object.account_id` |
| Изменение | `v1.rating` **Равен значению** `VIP`, **Сохранить в CRM**: Да |

Нужен запущенный стек с мок-CRM и пользователь с ролью `admin` или `editor` — см. [Быстрый старт](quick-start.md).

## Шаг 1. Откройте редактор

1. Войдите в интерфейс.
2. Нажмите **Создать процесс** в левом меню или кнопку **Создать процесс** на странице «Процессы».

## Шаг 2. Заполните конфигурацию процесса

В блоке **Конфигурация процесса**:

1. **Наименование процесса**: `Active deal → mark account as VIP` (подойдёт и русское название).
2. **Тип процесса**: оставьте **Процесс верхнего уровня**. Такой процесс запускается событиями CRM, а ведомый — только
   другим процессом.
3. **Тип объекта (object.type)**: выберите модуль сделок, `Deals`. Список приходит из CRM. В моке подписи модулей русские
   (`Сделки`), рядом показано техническое имя `Deals`. Кнопка ↻ рядом с полем (**Обновить список модулей из CRM**)
   перезагружает список.
4. **Приоритет**: оставьте `0` (**Меньше — выполняется раньше** среди процессов одного типа объекта).
5. **Однократный запуск для записи** не отмечайте.

На боковой панели **Переменные** справа появилась `object` — исходный объект типа `Deals`.

![Редактор процесса](../../images/screenshots/ru/04-process-edit-header.png)
*Редактор процесса: «Конфигурация процесса», «Блок 1. Условия запуска», начало «Блок 2. Действия» и панель «Переменные».*

## Шаг 3. Добавьте условие запуска

В блоке **Блок 1. Условия запуска**:

1. Нажмите **Добавить строку**.
2. **Поле (object.поле / v1.поле)**: `object.status`.
3. **Тип сравнения**: **Равен**.
4. **Зона сравнения**: **Значение**.
5. **Сравниваемое значение**: `Active`.

Все строки объединяются по «И». Если строк нет, процесс запускается на любое событие своего типа объекта.

## Шаг 4. Предзагрузите контрагента

В блоке **Блок 2. Действия** раскройте **Предзагрузка** и нажмите **Добавить строку**:

| Колонка | Значение |
|---|---|
| **Переменная** | `v1` |
| **Тип инициации** | **Из поля объекта** |
| **Поле объекта / переменной / значение** | `object.account_id` |
| **Модуль (тип объекта)** | `Accounts` |
| **Поле поиска** | `id` |

Поле поиска `id` загружает запись по идентификатору (`GET /Accounts/{id}`). Любое другое поле ищет по этому полю и берёт
первую найденную запись. Если ничего не найдено, `v1` получает значение `null`.

На боковой панели появилась `v1` с пометкой «загружена из CRM».

## Шаг 5. Измените рейтинг контрагента

Раскройте **Изменить объект / переменную** и нажмите **Изменение**:

| Колонка | Значение |
|---|---|
| **Объект / переменная (target)** | `v1.rating` |
| **Тип изменения** | **Равен значению** |
| **Новое значение** | `VIP` |
| **Сохранить в CRM** | отметьте **Да** |

Если **Сохранить в CRM** отмечено, переменная `v1` сохраняется в CRM сразу после изменения (`PUT /Accounts/{id}` только с
изменёнными полями). Если нет — изменение остаётся в памяти процесса. Тогда сохранение добавляют отдельной строкой кнопкой
**Сохранить в CRM**.

## Шаг 6. Сохраните

Нажмите **Сохранить и активировать**. Новый процесс по умолчанию неактивен: **Сохранить** оставляет его неактивным,
**Сохранить и активировать** сохраняет и сразу включает.

Если что-то заполнено неверно, редактор покажет красную плашку «Исправьте ошибки перед сохранением» со списком проблем.
Сервер повторяет проверки (например, «Variable "v9" is not defined at this point»). Подробнее —
в разделе [Процессы](../03-user-guide/processes.md).

После сохранения откроется карточка процесса:

![Карточка процесса](../../images/screenshots/ru/03-process-detail.png)
*Карточка процесса: свойства, «Блок 1. Условия запуска», «Блок 2. Предзагрузка» и «Блок 3. Действия» с меткой «+ сохранить в CRM».*

## Шаг 7. Проверьте на событии

Отправьте в стрим сделку со статусом `Active`:

```bash
curl -g "http://localhost:9502/test-event?module=Deals&set[status]=Active"
```

Мок генерирует сделку со случайным `account_id` и создаёт этого контрагента в мок-CRM. Отправьте второе событие с
`set[status]=Closed`: процесс на него не запустится.

На карточке процесса откройте вкладку **Журнал выполнения** (при необходимости нажмите **Обновить**):

![Журнал выполнения](../../images/screenshots/ru/10-process-executions.png)
*«Журнал выполнения»: по строке на запуск — источник «Событие CRM», статус, длительность, число повторов. Над таблицей — фильтры по статусу и периоду.*

Нажмите на ID выполнения, чтобы открыть его страницу:

![Детали выполнения](../../images/screenshots/ru/11-execution-detail-success.png)
*Завершённое выполнение: шаг 0 `preload` загрузил контрагента, шаг 1 `modify` изменил `v1.rating` и сохранил его в CRM.*

Раскройте строку шага, чтобы увидеть **Запрос (request_data)** и **Результат (result_data)**. У шага `modify` в результате
есть `old_value`, `new_value` и ответ на сохранение. Блок **Контекст выполнения** внизу показывает событие, переменные и
результат проверки каждого условия.

Проверьте контрагента в мок-CRM. `account_id` возьмите из события (вкладка **Событие (event)**):

```bash
curl -s http://localhost:9502/mock/objects/Accounts/<account_id>   # "rating":"VIP"
```

## Шаг 8. Проверка без CRM

Чтобы проверить процесс, не дожидаясь событий, нажмите **Выполнить (Run)** на карточке процесса. Введите JSON-объект,
например `{"id": "1", "module": "Deals", "status": "Active", "account_id": "<id существующего контрагента>"}`, и запустите.
См. [Ручной запуск и сброс](../03-user-guide/manual-run-and-reset.md).
